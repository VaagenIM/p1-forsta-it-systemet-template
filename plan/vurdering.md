# Vurdering i perioden

Du får **underveisvurdering mens du arbeider** og en **skriftlig sluttkommentar etter leveringsfristen**. Det ferdig leverte repoet er din individuelle systemforklaring. Du skal ikke gjennomføre en egen muntlig eller skriftlig prøve i tillegg.

**Leveringsfrist:** fredag 18. september 2026. Det som er sendt til GitHub innen fristen, er grunnlaget for sluttkommentaren. Se [leveringsstegene](../README.md#levering).

## Kompetansemål

Arbeidet vurderes opp mot disse kompetansemålene fra ITK02-01:

- utforske og beskrive komponenter i en driftsarkitektur (KM3942)
- utforske og beskrive relevante nettverksprotokoller, nettverkstjenester og serverroller (KM3948)
- gjøre rede for prinsipper og strukturer for skytjenester og virtuelle tjenester (KM3950)
- planlegge og dokumentere arbeidsprosesser og IT-løsninger (KM3947)
- feilsøke og rette feil ved hjelp av feilsøkingsstrategier og relevante rammeverk (KM3934)
- bruke og tilpasse kommunikasjonsform og fagterminologi i møte med brukere, kunder og fagmiljø (KM3936)
- beskrive og anvende relevante versjonskontrollsystemer i utviklingsprosjekter (KM3925)
- anvende relevant testmiljø og utføre testing tilpasset IT-løsningen som utvikles (KM3921)
- gjøre rede for hensikten med teknisk dokumentasjon og utarbeide teknisk dokumentasjon for IT-løsninger (KM3926)

Kilde: [Læreplan i vg2 informasjonsteknologi](https://www.udir.no/lk20/itk02-01/).

## Dette viser kompetansen din

| Kompetanse | Belegg i repoet |
|---|---|
| Finne og beskrive komponenter og roller i driftsarkitekturen | Komponentoversikt, fysisk topologi og systemoversikt |
| Forklare nettverksprotokoller, nettverkstjenester og serverroller | Logisk topologi, nettverksverdier og forklaring av minst én tjenestekjede |
| Forklare fysisk og virtuell infrastruktur | Systemoversikt og diagrammer som følger en tjeneste fra klient til virtuell ressurs, hypervisor og fysisk vert |
| Planlegge og dokumentere en arbeidsprosess | Sammenheng mellom planer, arbeidsfiler, kilder og ferdig dokumentasjon |
| Feilsøke systematisk og kontrollere løsningen | Dokumentert problem, undersøkelse, årsak, løsning og kontroll |
| Bruke versjonskontroll | Små, beskrivende registreringer i Git-historikken og endringer sendt til GitHub |
| Teste i relevant miljø | Observerte nettverksverdier, avtalte tester og dokumenterte resultater fra klient eller Linux-konsoll |
| Lage og formidle teknisk dokumentasjon som andre kan bruke | Et navigerbart repo med konsistente navn, fungerende lenker, diagrammer og presist, mottakertilpasset fagspråk |

## Underveisvurdering

Underveis får du tilbakemelding gjennom veiledning, ukeskontroller og fagfellekontroll. Tilbakemeldingen skal hjelpe deg med å velge et konkret forbedringssteg. Du skal bruke tilbakemeldingen til å forbedre repoet før fristen.

## Skriftlig sluttkommentar

Etter fristen får du en skriftlig kommentar til det ferdig leverte repoet. Kommentaren beskriver hva du viser innenfor de aktuelle kompetansemålene, og hva som er et naturlig neste steg i læringen.

## Før levering

- [ ] Repoet viser hele IT-laben med utgangspunkt i egen stasjon.
- [ ] Opplysningene stemmer med observasjoner og opplysninger fra den muntlige gjennomgangen.
- [ ] Diagrammer, tabeller og forklaringer stemmer overens.
- [ ] Diagrammene bruker samme ID-er som komponentoversikten, forklarer viktige relasjoner og inneholder ingen plassholdere.
- [ ] Minst ett problem er dokumentert med årsak, løsning og kontroll.
- [ ] Git-historikken viser utviklingen i arbeidet.
- [ ] En annen elev kan navigere i repoet og følge systemforklaringen.
